# AGENTS.md - OpenWrt Nightly Build Project

This file serves as a comprehensive knowledge base for AI agents working on the OpenWrt Nightly Build project. It contains architectural details, workflow specifications, and critical lessons learned to ensure consistent and high-quality contributions.

## 1. Project Architecture

The project is a GitHub Actions-based build system for OpenWrt firmware (specifically ImmortalWrt). It follows a modular design:

- **Source Definition**: Scripts in `scripts/` define the upstream repository and build dependencies.
- **Profiles**: Directory-based configurations in `profiles/` containing device-specific `.config` snippets, custom files, and build hooks.
- **Shared Config**: A central `configs/packages.conf` file for packages common across all device builds.
- **Build Core**: A reusable GitHub Actions workflow (`build.yml`) that orchestrates the entire process from environment setup to firmware collection.

**End-to-End Build Flow:**
1. **Trigger**: Push to `dev` branch or scheduled event on `main`.
2. **Environment Setup**: Install Ubuntu dependencies, clean runner disk space, and prepare `/workdir`.
3. **Cloning**: Fetch the specified OpenWrt/ImmortalWrt source.
4. **Feeds**: Update and install feeds, potentially modified by `pre-build.sh`.
5. **Configuration**:
    - Load `profiles/<device>/config`.
    - Merge `configs/packages.conf`.
    - Copy `profiles/<device>/files/` to OpenWrt root.
6. **Compilation**: Run `make download` followed by parallel `make`.
7. **Collection**: Extract firmware artifacts (`.img.gz`, `.bin`, etc.) and checksums.
8. **Distribution**: Upload artifacts or publish to GitHub Releases.

## 2. Branch Strategy

- **`main`**: Production branch.
    - Used for weekly scheduled builds (`nightly-release.yml`).
    - Produces production-ready firmware with GitHub Releases.
    - Tracks stable/release-quality configurations.
- **`dev`**: Development and testing branch.
    - Triggered on every push to `profiles/`, `scripts/`, or workflows.
    - Uses `dev-build.yml` for rapid testing.
    - Artifacts are uploaded as GitHub Action artifacts only (no public releases).

## 3. Workflow Details

The system uses GitHub Actions Reusable Workflows:

- **`.github/workflows/build.yml`**: The engine. Accepts inputs like `profile`, `source`, and `publish`. It handles all logic.
- **`.github/workflows/dev-build.yml`**: Calls `build.yml` with `publish: false`. Triggered by push events on the `dev` branch.
- **`.github/workflows/nightly-release.yml`**: Calls `build.yml` with `publish: true`. Triggered by cron schedule on the `main` branch.

## 4. Profile System

Each device is defined in `profiles/<name>/`:

- **`config`**: A minimal `.config` snippet. Contains `CONFIG_TARGET_*` and device-specific kernel modules (e.g., USB drivers).
- **`files/`**: Overlay directory. Files here are copied to the OpenWrt root (e.g., `etc/uci-defaults/` for first-boot scripts).
- **`hooks/`**:
    - **`pre-build.sh`**: Sourced after feeds update but before configuration. Use this to add third-party feeds or apply patches.
    - **`post-build.sh`**: Executed after successful compilation.

**Config Merging:**
The final `.config` is generated by:
1. `cp profiles/<profile>/config .config`
2. `grep -v '^\s*#' configs/packages.conf >> .config`
3. `make defconfig` (to expand dependencies and set defaults)

## 5. Third-party Feeds

Third-party repositories are typically added in `profiles/<profile>/hooks/pre-build.sh`.
Example additions (to be added as needed):
- `ddnsto`: `echo "src-git ddnsto https://github.com/linkease/ddnsto-openwrt.git" >> feeds.conf.default`
- `mosdns`: `echo "src-git mosdns https://github.com/sbwml/luci-app-mosdns.git" >> feeds.conf.default`

## 6. Key Files

| File | Purpose | Notes for Agents |
|------|---------|------------------|
| `.github/workflows/build.yml` | Main build logic | Central engine. Source of truth for the build process. |
| `scripts/common.sh` | Utility functions | Contains `log_info`, `cleanup_runner`. Source this first in scripts. |
| `scripts/source-immortalwrt.sh` | ImmortalWrt metadata | Defines `SOURCE_REPO_URL`, `SOURCE_REPO_BRANCH`, and deps. |
| `configs/packages.conf` | Shared package list | Format: `CONFIG_PACKAGE_name=y`. Shared by ALL profiles. |
| `profiles/*/config` | Device hardware config | Hardware-specific only. Avoid adding generic apps here. |
| `profiles/*/hooks/pre-build.sh` | Extension point | Use for `sed` on source code, patching, or extra feeds. |

## 7. Common Pitfalls & Lessons Learned

- **Reusable Workflow Booleans**: In `dev-build.yml` or `nightly-release.yml`, when calling `build.yml`, use `${{ inputs.ssh_debug || false }}` if passing from an input, but be aware that `build.yml` itself uses `inputs.` context. **Crucially**, use `inputs.` context, NOT `github.event.inputs.` for reusable workflow boolean parameters.
- **Sourcing Order**: In `build.yml`, always source `scripts/common.sh` BEFORE any other script that depends on its logging functions (like `log_info`).
- **Path References**: After `cd /workdir/openwrt`, the current working directory is NO LONGER the repository root. Use `$GITHUB_WORKSPACE` to reference files in the git repository (e.g., `cp $GITHUB_WORKSPACE/profiles/...`).
- **Shell Execution**: Run `pre-build.sh` with `source` or `.` if you need it to modify the current shell's environment variables, though direct execution is usually fine if it only modifies files.
- **BOM Encoding**: All text files (configs, scripts) MUST be **UTF-8 WITHOUT BOM**. Windows PowerShell adds BOM by default; ensure your editor/tooling uses pure UTF-8 to prevent shell script execution errors.

## 8. Build Variables

Environment variables available during the build:

- `SOURCE_REPO_URL`: Upstream OpenWrt repository.
- `SOURCE_REPO_BRANCH`: Target branch or tag.
- `SOURCE_NAME`: Name of the source (e.g., `immortalwrt`).
- `PROFILE`: Current device profile (e.g., `r2s`).
- `BUILD_DATE`: Format `YYYY.MM.DD`.
- `ARTIFACT_NAME`: Concatenation of source, profile, and date.
- `RELEASE_TAG`: Unique tag for GitHub Releases.
- `GITHUB_WORKSPACE`: Path to the checked-out repository.

## 9. Adding New Devices

1. **Create Directory**: `mkdir -p profiles/new-device/hooks`.
2. **Hardware Config**: Add `profiles/new-device/config` with target and device settings.
    - Run `make menuconfig` in a local OpenWrt environment to identify required symbols.
3. **Files (Optional)**: Add any custom configuration files to `profiles/new-device/files/`.
4. **Hooks (Optional)**: Create `pre-build.sh` or `post-build.sh`.
5. **Update Workflows**: Update the `profile` input `default` or choices in `.github/workflows/` if you want it to be selectable.

## 10. Debugging Failed Builds

- **Read the Logs**: Look for the `Compile firmware` step. If it fails, check the end of the log.
- **Single Thread Retry**: The `build.yml` automatically retries with `make -j1 V=s` if parallel build fails. Check this output for the actual compiler error.
- **Disk Space**: If you see `No space left on device`, verify `cleanup_runner` was called and check if the OpenWrt `dl/` directory has grown too large.
- **Missing Dependencies**: If a package fails to compile due to missing headers, update `SOURCE_BUILD_DEPS` in the relevant `scripts/source-*.sh` file.
- **SSH Debugging**: Set the `ssh_debug` input to `true` when manually triggering a workflow to get a live terminal via `tmate` on the runner.
